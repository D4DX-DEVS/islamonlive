# WordPress → Next.js migration runbook

The public site (`islamonlive.in`) is this Next.js 16 app. WordPress stays the
CMS at `admin.islamonlive.in` and is read over the REST API. This document is
the cutover plan, the URL-preservation contract, and the post-launch checks.

## 1. Architecture

```text
reader ──► Cloudflare ──► islamonlive.in (Next.js on Vercel, region bom1)
                              │  REST (server-side only, cached + tagged)
                              ▼
                         admin.islamonlive.in (WordPress + Yoast + plugin)
                              ▲
   /wp-content/* on the apex is proxied here by a next.config rewrite,
   so every indexed image URL keeps working unchanged.
```

| Concern | Where |
| --- | --- |
| Hosts / env | `src/lib/env.ts` — the only place `process.env` is read |
| WP client + pagination headers | `src/lib/wordpress.ts` |
| URL preservation (encoding, trailing slash, host swap) | `src/lib/urls.ts` |
| Yoast metadata + JSON-LD passthrough | `src/lib/seo.ts`, fallbacks in `src/lib/schema.ts` |
| Article HTML (links, media, embeds, shortcodes, script stripping) | `src/lib/content.ts` |
| Sitemaps at Yoast's paths | `src/lib/sitemap.ts`, `src/app/api/sitemap/**` |
| robots.txt (Cloudflare AI policy preserved) | `src/app/robots.txt/route.ts` |
| Redirects, rewrites, media proxy, trailing slash | `next.config.ts` |
| Cache purge webhook | `src/app/api/revalidate/route.ts` ← `wordpress-plugin/islamonlive-headless` |
| Legacy `?p=` / `?page_id=` / `?cat=` resolver | `src/app/go/[type]/[id]/route.ts` |
| Migration audit | `scripts/url-audit.mjs` |

## 2. The URL contract

Every address the old site advertised resolves on the new one **without changing a byte**:

| Old WordPress URL | New behaviour |
| --- | --- |
| `/{cat}/{slug}/`, `/{cat}/{sub}/{slug}/`, `/{cat}/{sub}/{sub2}/{slug}/` | 200, same path, self-canonical |
| percent-encoded Malayalam slugs (`%e0%b4…`, lowercase, with ZWJ `%e2%80%8d`) | 200 in either hex case; canonical/sitemap/JSON-LD emitted in WP's lowercase form |
| `/opinion/foo` (no slash) | 308 → `/opinion/foo/` (Next built-in; WP did the same with a 301) |
| `/{wrong-category}/{slug}/` | 308 → real permalink (no duplicate 200s) |
| `/category/{nested/path}/`, `/tag/{slug}/`, `/author/{slug}/`, `/{page-slug}/` | 200 |
| `/category/x/page/2/`, `/tag/x/page/2/`, `/author/x/page/2/`, `/authors-list/page/2/` | 200, self-canonical per page, cached (ISR); page number read from the path, never from `?page=` |
| `/category/x/page/1/` (any archive's explicit page 1) | 301 → the bare archive, from `next.config.ts` (no render, no WordPress call) |
| `/category/{leaf-only}/` (nested category by its leaf) | 308 → the real nested path, page number kept |
| `/?p=123`, `/?page_id=123`, `/?cat=60` | 301 → `/go/…/` → 301 → permalink (2 hops, by design: it is a lookup) |
| `/?s=term` | 301 → `/search/?q=term` (noindex) |
| `/{article}/feed/`, `/{article}/amp/`, `/authors/x/` | 301, single hop |
| `/feed/`, `/feed/*`, `/comments/feed/` | proxied to WordPress (RSS subscribers unaffected) |
| `/wp-content/*`, `/wp-includes/*` | proxied to WordPress — image URLs unchanged |
| `/wp-admin/*`, `/wp-login.php`, `/xmlrpc.php`, `/wp-json/*` | 301 → `admin.islamonlive.in` |
| `/sitemap_index.xml`, `/post-sitemap.xml` … `/post-sitemap23.xml`, `/page-sitemap.xml`, `/category-sitemap.xml`, `/post_tag-sitemapN.xml`, `/author-sitemapN.xml`, `/news-sitemap.xml`, `/main-sitemap.xsl` | generated by Next at the identical paths, 1000 URLs per file |
| anything else | real 404 (content routes deliberately have no `loading.tsx`, so the status is not locked at 200 by streaming) |

Status codes you will see and why: everything authored in `next.config.ts`
is a **301**. The two 308s are Next's — the trailing-slash normaliser and
`permanentRedirect()` inside a page (a Server Component cannot pick 301).
Google treats 308 exactly as 301 for consolidation.

One Next.js quirk to know before anyone files it as a bug: the **first,
uncached** answer at a page-level 308 (an article requested under the wrong
category, a nested category by its leaf alone) carries the `Location` header
**twice, with the same value** — Next 16.3.0–16.3.4 replays the render's
headers with `appendHeader` in `next-server.js`. The cached answers that
follow carry it once. Browsers and Googlebot accept identical duplicates (a
*different* second value is what Chrome rejects), the static redirects above
are not affected, and there is no app-level fix; re-check on a Next upgrade.

## 3. Environment

Copy `.env.example`. Production values:

```text
WORDPRESS_API_URL=https://admin.islamonlive.in/wp-json/wp/v2
NEXT_PUBLIC_WORDPRESS_URL=https://admin.islamonlive.in
NEXT_PUBLIC_SITE_URL=https://islamonlive.in
REVALIDATION_SECRET=<openssl rand -hex 32>
```

- Set them in the Vercel project (Production **and** Preview), never in `vercel.json`.
- The local `.env.local` carries all four as of 2026-09-08, with
  `WORDPRESS_API_URL=https://islamonlive.in/wp-json/wp/v2` — the apex, because
  that is where WordPress answers today. Flip it and `NEXT_PUBLIC_WORDPRESS_URL`
  to `admin.islamonlive.in` on cutover day; `next.config.ts` reads them at
  build/start, so restart the dev server after changing them.
- `REVALIDATION_SECRET` in `.env.local` is the value to paste into the plugin's
  settings page (Settings → Headless Frontend). Rotate both together.
- `vercel.json` still carries `NEXT_PUBLIC_WORDPRESS_URL=https://islamonlive.in`
  from the single-host era. Remove that `env` block once the dashboard values
  exist, or it will override them.
- The config detects WP host == site host (`SPLIT_HOSTS=false`) and disables
  the proxy/redirect rules so a single-host checkout cannot loop. That is
  the state today: `admin.islamonlive.in` had no DNS on 2026-09-08.
- Staging: same WordPress, `NEXT_PUBLIC_SITE_URL=https://staging.islamonlive.in`,
  and protect it (Vercel password / Cloudflare Access) so it is never indexed.

## 4. WordPress side

1. **Give WordPress its subdomain.** Point `admin.islamonlive.in` at the WP
   origin. In `wp-config.php` set `WP_SITEURL` to `https://admin.islamonlive.in`
   and keep `WP_HOME` at `https://islamonlive.in` — permalinks, Yoast
   canonicals and the JSON-LD graph then already carry the public host. (The
   frontend rewrites hosts defensively either way, so the reverse also works.)
2. **Install the plugin.** Upload `wordpress-plugin/islamonlive-headless/` to
   `wp-content/plugins/`, activate, then Settings → Headless Frontend:
   frontend URL `https://islamonlive.in`, shared secret = `REVALIDATION_SECRET`.
   Or define `IOL_FRONTEND_URL` / `IOL_REVALIDATION_SECRET` in `wp-config.php`.
   Press *Send a test refresh* — it must say `200`.
   The webhook posts to `/api/revalidate/` **with the trailing slash**; without
   it Next answers 308 and a non-blocking POST is lost.
3. **Confirm the REST API exposes Yoast.** `GET /wp-json/wp/v2/posts?per_page=1`
   must include `yoast_head_json`. It does today.
4. **CORS.** The plugin replaces WordPress's `Access-Control-Allow-Origin: *`
   with the frontend origin only. The frontend never calls WP from the browser,
   so nothing else needs an allow entry.
5. **The CMS host must not be indexed.** The theme still renders every
   article on `admin.islamonlive.in`. The plugin (1.1.0) handles it: every
   front-end response there carries `X-Robots-Tag: noindex, nofollow`, and a
   browser navigation (`Sec-Fetch-Dest: document`) is 301'd to the same path
   on the public site; feeds, previews, robots.txt and the frontend's own
   server-side reads are left alone. Both hooks are inert while WordPress
   still answers on the apex. Verify after the split:
   `curl -sI https://admin.islamonlive.in/<any-post>/` → `200` with the
   `X-Robots-Tag`; add `-H "Sec-Fetch-Dest: document"` → `301` to
   `https://islamonlive.in/<any-post>/`.
   **Never** tick Settings → Reading → *Discourage search engines* to achieve
   this: Yoast then emits `noindex` in `yoast_head_json.robots`, the frontend
   copies Yoast's robots verbatim, and the public site de-indexes itself.
6. **Cloudflare.** The apex robots.txt is now served by Next and carries the
   Content-Signal / AI-crawler block verbatim; if the "managed robots.txt"
   feature stays on for the apex it will prepend a second copy — turn it off
   for `islamonlive.in` or accept the duplicate block (harmless).
   Optional later optimisation: a Cloudflare origin rule sending
   `/wp-content/*` straight to WP keeps image bytes off Vercel; the Next rewrite
   remains as the fallback.

## 5. Cutover, in order

1. Deploy the frontend to a **staging** host with the production env (WP on
   `admin.`). Verify DNS for `admin.islamonlive.in` resolves first.
2. Run the audit against staging on the old sitemaps (section 6). Fix
   anything with an `issues` value.
3. Back up WordPress files and database (hosting snapshot + `wp db export`).
4. Search Console: note the current *Pages → Indexed* count and export
   *Links → Top linked pages* (your backlink baseline).
5. Point `islamonlive.in` at Vercel. Keep `admin.` on WP. Do not purge
   Cloudflare cache until the apex answers correctly.
6. Immediately after: `curl -I https://islamonlive.in/sitemap_index.xml`,
   `/robots.txt`, an old Malayalam article URL, `/wp-content/uploads/<any>`,
   `/feed/`, plus the two `admin.` checks from section 4 step 5. Then re-run
   the audit against production.
6a. `node scripts/warm-sitemaps.mjs https://islamonlive.in` — renders all 33
   sitemap files once (cold, each takes 10–20 s; warm, milliseconds) so
   Googlebot never meets the cold one. Repeat after every deploy.
7. Search Console → Sitemaps: the existing `sitemap_index.xml` submission is
   still valid; press *resubmit*. Use *URL Inspection → Test live URL* on a
   handful of top articles. Do **not** use the URL-removal tool.
8. Watch for a week: GSC *Pages* (Not found / Redirect / Duplicate-without-
   canonical), *Crawl stats* (5xx), Vercel logs for `/api/revalidate/` 401s
   (wrong secret) and 503s (secret unset).

Rollback is DNS only: repoint the apex at WordPress. Nothing in WP changes
during cutover, so it is reversible in minutes.

## 6. URL audit

```text
node scripts/url-audit.mjs --base https://staging.islamonlive.in \
  --sitemap https://islamonlive.in/post-sitemap.xml \
  --sitemap https://islamonlive.in/post-sitemap12.xml \
  --sitemap https://islamonlive.in/post-sitemap23.xml \
  --sitemap https://islamonlive.in/category-sitemap.xml \
  --sitemap https://islamonlive.in/page-sitemap.xml \
  --out audit-staging.csv
```

Run it before the old sitemaps are gone (they are read from the current WP
site). Add `--sitemap` lines for every file in `sitemap_index.xml` for the
full 22,297-URL pass, plus `--urls` with the top pages from Search Console
*Performance* and the top linked pages export. The CSV is the migration
report: old URL, new URL, status, redirect destination, canonical, title,
description, indexability, detected issues. Non-zero exit = something to fix.

## 7. Backlinks

Backlink equity survives a migration when the linked URL still answers 200 at
the same address, or 301s once to its replacement. The contract in section 2
guarantees that for every URL pattern the old site produced. To verify with
data rather than by construction: export *Links → Top linked pages* from
Search Console before cutover, feed those URLs to the audit with `--urls`,
and require zero issues. After launch, the same GSC report should show the
same pages with the same counts within a few weeks; a drop points at a URL
that changed, which the audit will have flagged.

## 9. Open items to settle in WordPress before cutover

- **`/elementor-122398/`, `/elementor-122411/`** (and check `/elementor-119103/`):
  Elementor *template* pages that Yoast listed in `page-sitemap.xml`. WordPress
  itself answers 500 when the REST API renders their content (with or without
  `_embed`), so the frontend answers 500 too. They are not content — trash them
  or set them to noindex in Yoast, then remove them from the audit list.
- ~~**`/authors-list/`**~~ — settled 2026-09-08. The WP page's body is a
  JetEngine listing widget (empty over REST), so the frontend now serves its
  own directory at `src/app/authors-list/[[...page]]/page.tsx`: the users
  endpoint, A→Z, 60 a page (`/authors-list/page/N/`, each page self-canonical
  and cached, past the end → 404). Nothing to do in WordPress; the WP page can
  stay or go.
- **`watch-sitemap.xml` and `jet-menu-sitemap.xml`** were in Yoast's index and
  are not in this app's: `/watch/*` (the small `watch` post type) is 301'd to
  `/watch-videos/`, and `jet-menu` is JetEngine menu data, not content. Set
  the `jet-menu` post type to noindex in Yoast so the CMS host never
  advertises it either; Search Console will simply stop seeing the two files.
- **WordPress site language is `en-GB`** (Settings → General): Yoast derives
  every node's `inLanguage` from it. The frontend rewrites it to `ml`; set it
  to Malayalam so the CMS agrees.
- **Yoast templates** (Search Appearance): the archive description template
  reads "…a compelete malayalam islamic web portal on islam, muslim, middile
  east…" on every category and author page (the frontend ignores it and uses
  the term's own description), and the post title template appends the
  61-character tagline to every article (the frontend keeps Yoast's article
  titles because they are what ranks today — shorten the template and they
  shorten everywhere).
- **Yoast descriptions on individual posts**: several sampled are cut
  mid-sentence, in English on Malayalam posts, or just `Title |` (2012-era);
  the privacy-policy description is about the site, not the policy. They pass
  through as written. Editorial.
- **Bylines**: posts attributed to the `islamonlive` admin account show no
  named writer, and the author page's heading is that account's display name.
  Reassign, or give the staff account a real name and bio.
- **Featured images under 696 px** on many older posts (sampled 650, 400,
  289 px wide) keep them out of Google's large-image results and Discover.
- **AI-search decisions the publisher owns**: the crawler list above; the
  Google "set as preferred source" button (needs the exact snippet from
  Search Central, published 2026-08-20 — not guessed here); the viewport meta
  that disables pinch-zoom (deliberate, fails WCAG 1.4.4 — one line in
  `src/app/layout.tsx` to reverse).
- **Full Content-Security-Policy**: the headers now include HSTS,
  `Permissions-Policy` and CSP `frame-ancestors 'self'`. A complete CSP needs
  an allow-list for YouTube, Instagram, OneSignal, the WP media host and
  inline JSON-LD, tested page by page in `Content-Security-Policy-Report-Only`
  first.
- **Podcast artwork** is hot-linked from the podcast host's CDN at original
  size (880 KB on the home page). Route it through the media proxy once the
  artwork host is settled; Instagram preview images are signed URLs and
  cannot be resized.
- **Posts without a featured image** (several thousand of the oldest): they now
  fall back to `/icon-512.png` for `og:image`. If a proper 1200×630 default
  social image exists, put it in `public/` and change the fallback in
  `src/lib/seo.ts`.
- **AI-crawler policy** (publisher decision, not a defect): `robots.txt`
  carries the live site's Cloudflare list verbatim — `Disallow: /` for GPTBot,
  ClaudeBot, Google-Extended, CCBot, Bytespider, Amazonbot, Applebot-Extended,
  meta-externalagent, CloudflareBrowserRenderingCrawler, plus
  `Content-Signal: search=yes,ai-train=no,use=reference`. That keeps the
  archive out of training sets, and also out of ChatGPT search (GPTBot) and
  Claude's web results (ClaudeBot). OAI-SearchBot and PerplexityBot are not
  blocked. Google-Extended does not affect Google Search, AI Overviews or AI
  Mode. If the publisher wants AI-search referrals without AI training, the
  minimal change is to drop GPTBot and ClaudeBot from `BLOCKED_AI_AGENTS` in
  `src/app/robots.txt/route.ts` and keep the rest — see
  `docs/seo-audit/findings/geo.md`.
- **Cloudflare managed robots.txt**: if the apex stays proxied through
  Cloudflare after the move and that feature stays on, Cloudflare prepends its
  own copy of the same block. Either switch it off for `islamonlive.in`
  (dashboard → Security → Bots → *Manage AI robots.txt* / Content Signals), or
  set `ROBOTS_CLOUDFLARE_MANAGED=1` in Vercel so this app omits its copy. With
  the apex on Vercel DNS-only (grey cloud) there is no injection and nothing
  to do.

## 10. Second pass — 2026-09-08 (search, archives, error pages)

Changes after the first verification round, all in the frontend:

- **Search relevance**: every `search=` request now carries
  `orderby=relevance` (title matches first, then body, then date). REST's
  default was newest-first, which buried exact title matches.
- **Search across both Malayalam encodings** (`src/lib/search.ts`): the archive
  spells the chillu letters both as single code points and as consonant +
  virama + ZWJ, and uses the zero-width non-joiner inconsistently. Measured:
  "ഖുർആൻ" 1,257 posts vs "ഖുര്‍ആന്‍" 2,444; "ഇസ്‌ലാം" 2,349 vs "ഇസ്ലാം" 1,211.
  A query touched by either split is run per spelling (≤4 requests, parallel,
  cached) and the relevance-ordered lists are interleaved; the count shown is
  the sum. The type-ahead (`/api/suggest/`) does the same. Verified:
  `/search/?q=ഖുർആൻ` reports 3,701 (= 1,257 + 2,444) and 24 cards on page 1.
- **Query hygiene**: control characters stripped, whitespace folded, capped at
  120 characters before anything reaches WordPress; a proper no-results panel
  with links to the app's own sections; result count and "page N of M" shown.
- **Category archives list the whole subtree** through the REST object form
  `categories[terms][]=ID&categories[include_children]=true` (WP 5.7+), the
  same set WordPress's own archive shows — shariah alone is 570 posts, with
  descendants 1,931. The old direct-children lookup missed grandchildren.
- **Empty archives are 404s**: a category, tag or author page with no posts
  (and any page number past the end) answers 404, as WordPress does; a 200
  with an empty list is a soft 404. Verified `/category/listen/` → 404.
- **404 page** carries its own title ("Page not found"), a search box and
  links to the app's own sections. Note: the 404 status and title are in the
  response, but the body is delivered as a client-rendered shell — that is how
  Next 16 handles `notFound()` thrown from a dynamic segment
  (`NEXT_HTTP_ERROR_FALLBACK`), verified identical in dev and `next start`,
  and not something the app can change. Crawlers only need the status.
- **RSS autodiscovery** `<link rel="alternate" type="application/rss+xml">`
  in the document head, as WordPress printed it.
- **`ROBOTS_CLOUDFLARE_MANAGED`** build-time flag (see section 9).
- `/saved/` card titles: `line-clamp-2 block` → `line-clamp-2` (Tailwind v4
  emits `block` after the clamp, cancelling it).
- Full SEO / GEO audit of the production build with the `seo-audit` skill's
  agents: `docs/seo-audit/` (findings per category, action plan).

## 11. Third pass — 2026-09-08 (everything the audit put on the frontend)

The seven audit agents scored the build 64/100 (`docs/seo-audit/FULL-AUDIT-REPORT.md`).
Every item they assigned to the frontend was fixed and re-verified against a
fresh production build with 107 HTTP probes, the 725-URL replay of the old
Yoast sitemaps and browser checks at 375/1280 px:

- **Caching**: no content route was cached before — articles, archives and WP
  pages rendered on every request. `generateStaticParams()` on every dynamic
  route and path-based pagination (`/category/x/page/2/`,
  `/authors-list/page/2/`; the routes never read `searchParams`) make them all
  ISR (`s-maxage=60, stale-while-revalidate`). The explicit `/page/1/` of any
  archive is a static 301 in `next.config.ts`.
- **Titles**: `cleanTitle()` removes the doubled site name + tagline Yoast's
  taxonomy template produced (`News | Islamonlive.in`, `News - Page 2 |
  Islamonlive.in`); `og:url` equals the page's own canonical; the home page has
  site-wide OG/Twitter defaults; the search page's title carries the query.
- **JSON-LD**: Yoast's graph is normalised at every depth — `inLanguage: ml`,
  one Organization (name, `/logo.png`, sameAs with YouTube and Instagram,
  founding date, office address, editorial email, parent D4 Media), one
  WebSite with the `/search/?q=` action, `dateModified` on every Article and
  WebPage, `ProfilePage.mainEntity`; About/Contact/Authors carry the site
  nodes and point their `mainEntity` at the Organization.
- **Articles**: visible breadcrumb, author bio, "Updated" date when the edit is
  a day or more after publication, trailing-slash byline links, descriptions
  trimmed on a sentence or word boundary.
- **Archives**: server-rendered Previous/Next links to `/page/N/` under the
  scroll-loading list (crawlers never scroll); a page past the end and an
  unknown term are 404s; the leaf-only path of a nested category is a 308 to
  the real path.
- **Sitemaps**: `page-sitemap.xml` keeps only the WP pages that actually render
  here (checked one page at a time — asking WordPress for every page's content
  in one request makes Elementor 500), `lastmod` in the index only where
  WordPress can say, no `changefreq`/`priority`, styled news file,
  `scripts/warm-sitemaps.mjs` for the cold start.
- **Home**: the site is the h1 (visually hidden), stories are h2; the YouTube
  player is a click-to-play facade; four font preloads instead of ten.
- **Headers**: HSTS (2 years), `Permissions-Policy`, CSP `frame-ancestors
  'self'` added to the existing three.
- **Payload**: WordPress `_links` blocks stripped from every list; `/llms.txt`
  published (optional; Google ignores it).
- **Redirects**: `permanentRedirect()` now lives in the page only; the
  duplicate-`Location` quirk described in section 2 is Next's and remains.
- **725-URL audit**: 717 × 200, 4 × 301 (single hop), 3 × 500 (the Elementor
  templates — WordPress), 1 × 404 (`/author/hasan-abu/`, an account WordPress
  hides from REST — WordPress); zero canonical mismatches; the only
  "missing description" rows are 2012 posts whose bodies are empty in
  WordPress (five under `/islam-padanam/` in the sample).

What is left is listed with its owner in `docs/seo-audit/ACTION-PLAN.md` and
in section 9 above: none of it is frontend code.
